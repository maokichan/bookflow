## 1. 一句话现状

**书稿流水线 MVP 已端到端跑通并通过真实书首轮检验**：PDF → 分型块图 → 90 页页图 → 浏览器工作台（人工校对 #1）→ 裁决日志 → 回放器推进块图。
当前 `data/` 里装的是第一个真实科目：鲍德里亚《为何一切尚未消失》（南京大学出版社，90 页，扫描+OCR 文本层），**工作台已就绪、人工校对尚未开始**。

## 2. 决策链（为什么会是这个样子）

按时间顺序，每条都是与用户对齐过的：

1. book 项目（`../book/`，化学兄弟传记）证明了 LLM 校对可行，但它是干净 docx 上的半程——用户要求回到 PDF 源头重新设计**真实工作流**。
2. 架构定稿于 [`../book/书稿流水线架构.md`](../book/书稿流水线架构.md)：块图（五类分型+未分型态）、七级状态机（机器只贴条子、人工独占锁定态）、三域机器校对（形式/对应/语义）、五条宪法、苦涩教训风险登记。**本文不重复架构，只补充实现层事实。**
3. 界面决策：长期归 TuRead Pro，**短期不做 TuRead**，用本地无服务 HTML 工作台占位，写回走 append-only 裁决日志。
4. 栈决策：**全 JS/TS**（一份实现、两个宿主：Node CLI 跑批 + 将来 Electron）。`book/` 里的 Python 身份是原型，冻结归档、不删；真正有积累的只有 lint 调参史和 sysprompt，将来移植收割。
5. 翻译层决策：传统 MT API 在书的规模上被 LLM 淘汰（价格同量级、质量差、人工返工更多）；具体 LLM 引擎未定——**架构不假设供应商**。
6. OCR 决策：异构多型（本地免费腿 + 云端 VLM + 分歧即信号）；**本地检查小模型（QE 类）不上**，检查靠规则和交叉验证。
7. 悲观假设：一切 PDF 按最差情况对待——真实书首轮检验直接印证（见 §6）。

## 3. 项目文件导览（D:\PROJECT\bookflow）

| 文件 | 干什么 |
| --- | --- |
| `src/model.ts` | 块图数据模型：五类分型、七级状态、权限表 `GATE_TRANSITIONS`、路径常量。单一事实源。 |
| `src/extract.ts` | S0+S1 合并跑：pdfjs 文本层 → 行聚类（4.5pt 容差吸上标）→ 分型 → 段落重组（行距×1.3 + 首行缩进双信号）→ `data/blockgraph.json` |
| `src/renderpages.ts` | 页图渲染：pdfjs + @napi-rs/canvas，`CanvasFactory` 注入（见 §6 第 1 课），scale=2 |
| `src/workbench-template.html` | 工作台客户端（vanilla JS）：台阶分箱 / 图文锚点对照 / 键盘裁决 / 日志下载 / localStorage 崩溃兜底 |
| `src/exportwb.ts` | 工作台导出器：块图 JSON 内联进单文件 HTML，页图走相对路径 `../data/pages/` |
| `src/replay.ts` | **块图的唯一写者**：消费 `inbox/*.jsonl`，校验前置状态后应用（gate/edit/reclassify），非法动作拒绝并报告，已消费日志归档 `inbox/processed/` |
| `test/smoke.ts` | 端到端冒烟：抽取断言→页图→导出→合成裁决回放→断言→自动重置为干净 typed 态 |
| `testbook/main.typ` + `scripts/build-testbook.mjs` | Typst 受控测试书（章节/页眉页码/脚注/引语/粗体/中英混排），复用 `../book/tools/typst.exe` |
| `data/` | 单书 MVP 的现场：`blockgraph.json` + `pages/` + `source/`（科目 PDF 副本） |
| `workbench/workbench.html` | 当前科目的工作台产物（可再生、可弃） |

**bookflow 不是 git 仓库**（未 init）。工作台和数据都是可再生品，代码丢不了。

## 4. 操作环（给不在这个会话里的人）

```
npm run extract && npm run render && npm run export   # 重建科目现场
# 双击 workbench/workbench.html →
#   J/K 移动 · E 改文(Enter 提交) · G 盖章(原文已定) · Y 退回 · T 改型 · I 缩放 · , . 翻页 · S 导出日志 · Tab 切箱
# 下载的 adjudication-*.jsonl 放进 inbox/ →
npm run replay                                        # 块图推进，日志归档
npm run export                                        # 工作台反映新状态
npm run smoke                                         # 全链路回归（跑完自动重置）
```

**铁律**：图书馆 `D:\DATABASE\图书馆` **只读**，科目一律先复制进 `data/source/`；
不要手工编辑 `blockgraph.json`——它只有一个写者（回放器），手改会造成裁决日志与状态互斥。

## 5. 真实书首轮检验（第一科目的战报）

科目：鲍德里亚《为何一切尚未消失》→ `data/source/real-01-baudrillard.pdf`。
图书馆 339 本 PDF，抽样 9 本：**7 本纯扫描**（悲观假设坐实，OCR 腿是硬需求）、本文是**扫描+嵌入 OCR 层**（A4 陷阱型）、正文层 88 页全部 ≥95% 干净。

暴露并已修复的三个缺陷（修复均有实测数据依据，详见会话或代码注释）：

1. **渲染崩溃**：pdfjs legacy 的 `NodeCanvasFactory` 硬性 `require("canvas")`（node-canvas，Windows/Node24 难装）。修复 = 向 `getDocument({ CanvasFactory })` 注入基于 `@napi-rs/canvas` 的同契约工厂。
2. **书眉排页脚**（中文书惯例）：新增底部区跨页重复聚类，50 页书眉正确归附着块。
3. **脚注判定重构**：本书实测四层字号——正文 9.5 / 引文体 8.5 / 脚注 7.0 / 书眉页码 6.5。纯字号阈值切不开（引文行两次误判）。最终空域信号：**"正文最后一行（fs>0.92×基准）之下才是脚注区"**——引文体下面还有正文，脚注下面只有书眉页码。真脚注全中，annotation 从 150 收敛到 64。

当前分型：888 块 = flow 662 + structure 9 + annotation 64 + furniture 153。

**已知不完美（人工 #1 的正常食粮，不是 bug 报告）**：

- 正文 OCR 层有 CJK 内部伪空格（"我 完 全赞同"）和被 OCR 成 `®` 的脚注标记 → 将来 S2 清洗槽位 + 形式域检查器的首批靶子；
- 封面/版权页（前 4 页）OCR 层是乱码 → 工作台里用 T 键划给附着/未分型；
- 个别 OCR 噪音书眉（"为何.切尚米消失"）因文本失真逃过精确重复聚类，混在注释箱；
- 中英边界偶有缺空格（"聊B 面"，typst 间距小于抽取阈值）；
- **块 ID 跨书不唯一**（`p01-b002` 谁的书都有）——单书 MVP 无碍，**多书支持前必须加书前缀**，否则裁决日志会串书。

## 7. 建议的接续顺序（按价值/依赖排）

1. **人工 #1 试跑**（本机前 10 页）——收集体感：键盘流是否顺手、OCR 噪音的实际处理成本、条子（将来机器检查）应该长什么样。这是所有下游设计的依据。
2. **S2 清洗槽位**：CJK 伪空格归一、标点归一——机械规则，能让待校块的可读性立涨，也顺便给形式域检查器打底。
3. **OCR 腿**（PaddleOCR-on-ONNX 本地打底）——解锁图书馆里 7/9 的扫描馆藏，分歧信号架构已定。
4. 多书支持（块 ID 加书前缀 + 科目切换）——在做任何第二批科目之前必须先做。
5. 翻译 S3 → 三域检查 S5 → Typst 重排版（book 项目有现成 Typst 管线可参考）。
