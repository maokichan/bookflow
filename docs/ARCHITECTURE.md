# bookflow 架构：书籍状态管理与功能层级

> 2026-10-05 与用户逐条对齐定稿。上位文档 [`../../book/书稿流水线架构.md`](../../book/书稿流水线架构.md)
> 的五条宪法（覆盖率守恒 / 单一事实源 / 可复现 / 注意力导流 / 权限层独立于能力层）继续全部有效；
> 本文定义 bookflow 程序自身的层面结构。文档记录意图与不变量，实现细节归代码与 README。

## 1. 两层结构

- **书籍状态管理**：一个独立的层面，是整个程序的入口与骨架。书在这一层被导入、登记；
  每本书走到流水线哪一步、正有什么在进行，在这一层被追踪。人通过这一层进入某本书。
- **功能层级**：挂在书籍状态管理之内的附属层，装"能力及其配置与运行"——
  OCR 云端配置、OCR 本地配置、LLM API 配置，以及任务队列、任务记录、用量。
- **行为 = 对某本书施加某种能力**。进入书之后的行为：OCR、MT（机器翻译）、
  人工校对两次（原文 / 双语）、机器校对三次（形式 / 对应 / 语义三域）——各自独立成动作，同出一个入口。
- **书级流水线**：导入 → 预处理 → 识别 → 原文校对 → 翻译 → 双语校对 → 机器检查。
  预处理（对比度/降噪/锐化，手动参数 + 按百分比采样预览）在识别之前，确认后落盘全量页图——
  **页图集合即预处理产物**，OCR 直接消费它，参数指纹绑定：参数一改产物即过期、需重新确认。
  存储位置在首用时于主界面确定，运行期一切产物与运行时文件都在库根之下。
- **版本管理（git 风格）**：书籍处理状态可显式存版（工作台 Ctrl+S）与恢复；
  阶段完成点自动存版；做到后面才发现前面错了，回版本列表恢复重做。
- 全覆盖论证：状态层保证每个行为有入口（每本书的每个阶段都有位置），
  功能层保证每种能力有配置位（每个引擎都有家）。

## 2. 书的状态：两层状态机

- 块有七级台阶（raw → … → 已采纳，见上位架构 §1），**书也有阶段台阶**。
  书籍状态管理管书级，进书后的行为操作块级——状态分箱的回报从块级延续到书级。
- **书级状态 = 阶段完成度 + 在途任务**。点击一本书，先看到它的状态页：
  哪些阶段做完了、什么正在进行（"OCR 进行中"也是状态）、哪些行为此刻可以发起；行为从状态页发起。

## 3. 产物溯源（引擎绑定）

- **一切产物携带出生证明**：由哪个引擎、什么配置做出。换引擎前后，系统随时能回答
  "这本书的哪些产物是旧引擎做的"——不产生说不清的混血产物，重跑与标记不一致有据可依。
- 这条直接服务于可复现宪法（变换 = 输入 + 已记录参数）：把"参数有记录"升级为"产物有来源"。
- 块模型中已有的"提取来源与置信"字段是此原则在块级的存在，此原则推广到一切产物。

## 4. 异步与队列

- **行为是异步任务**：OCR 一本书绝不阻塞整个程序；队列承载多个任务；
  不同书的行为并行、OCR 与 MT 同时进行都是正常形态（并发度是配置不是架构）。
- **单一写者原则在并发下继续成立**：并行的任务各自产出自己的中间产物（OCR 意见、译文、检查条子），
  对块图的正式写入仍走唯一写者——"任务能并行、事实源不混乱"由这条保证。
- 同一书内存在阶段闸门依赖（未抽取不能渲染、未定原文不能翻译），由状态机天然约束任务的先后。

## 5. 范围排除（有意，不是缺陷）

- **一本书 = 一个扫描版**。同一本书不同扫描版之间的同步、对齐、合并不在程序设计范围内，
  数据模型不做书籍身份的版本分层（与 TuRead 书库模型刻意不同）。

## 6. 与上位宪法的关系

- 五条宪法全部继续有效；权限层独立于能力层在 UI 上的直接映射：
  状态页上"机器做了什么"与"人章了什么"永远可分辨。
- 策略位的"可换"获得物理位置：引擎配置住在功能层级——换引擎不动书的状态，推进书不动引擎配置。
- 苦涩教训防御不变：分型是接口不是实现；意见源数量是配置；三域是角色不是进程。

## 7. 当前落地形态（随实现更新）

- **library/ 注册表**：每本书一个目录（源 PDF 副本、块图、页图、裁决日志收发箱、任务记录），
  `library/index.json` 是科目登记处——书被项目记住，不再有隐蔽默认科目。
- **本地服务 + 书架页**：一个本地端口同时服务书架 UI、各书工作台与页图；
  行为以任务形式入队执行（当前串行，并发度留作配置）。
- **一份实现多个宿主**：流水线工具保持 CLI 可独立运行（`--book <id>` 寻址），
  本地服务的队列只是 CLI 的第三宿主（前两个：命令行、将来的桌面壳）。
- 尚未点亮的行为（OCR / MT / 机器三域）在状态页以"未点亮"出现——策略位语义，不是缺失。
